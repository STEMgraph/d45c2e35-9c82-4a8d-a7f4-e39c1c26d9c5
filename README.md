# Cpp: Lambda Expressions and Captures

> In this exercise you write anonymous functions directly at the call of an algorithm, capture local variables by value and by reference, see that a lambda is a class generated by the compiler, and run into the classic trap of a dangling capture. No `sudo` is required.

## Introduction

A **lambda expression** is a function object written in place: `[capture](parameters) { body }`. The compiler turns it into an unnamed class with an `operator()` and, for every captured variable, a member. You wrote such classes by hand in the previous exercise; the lambda is the short form, and the comparison, the predicate or the transformation now stands right where the algorithm uses it.

The **capture list** in the square brackets decides which variables of the surrounding function the lambda may use, and how: `[x]` copies `x` into the lambda, `[&x]` refers to the original, `[=]` and `[&]` do this for everything the body uses. A lambda with captures is often called a **closure**.

### Task 1: The first lambda

```bash
mkdir -p ~/cpp-lambda && cd ~/cpp-lambda
```

```c++
// file: first_lambda.cpp
#include <iostream>
#include <type_traits>

int main() {
    // 1) defined and called immediately
    [](){ std::cout << "Hello, lambda!" << std::endl; }();

    // 2) stored in a variable of deduced type, then called
    auto add = [](int a, int b) { return a + b; };
    std::cout << "add(3, 4) = " << add(3, 4) << std::endl;

    // 3) with an explicit return type
    auto half = [](int x) -> double { return x / 2.0; };
    std::cout << "half(5) = " << half(5) << std::endl;

    // 4) what is a lambda, really?
    std::cout << "sizeof(add) = " << sizeof(add) << std::endl;
    auto same_shape = [](int a, int b) { return a + b; };
    std::cout << "same type as add: " << std::is_same<decltype(add), decltype(same_shape)>::value << std::endl;
}
```

```bash
g++ -std=c++17 -Wall -Wextra first_lambda.cpp -o first_lambda && ./first_lambda
```

The first line defines and calls a lambda in one go (note the `()` at the end). `auto` is the only way to name the type of a lambda, because the compiler generates it. It is a class with a size of one byte, and two lambdas with identical text still have **different** types. Change the return type of `half` to `-> int` and explain the output.

### Task 2: Lambdas at the call of an algorithm

```c++
// file: algorithms.cpp
#include <algorithm>
#include <iostream>
#include <numeric>
#include <string>
#include <vector>

struct Person {
    std::string name;
    int         age;
};

int main() {
    std::vector<int> v{5, 2, 9, 1, 3, 8};

    // The comparison and the predicate sit right where they are used.
    std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });
    for (int x : v) std::cout << x << " ";
    std::cout << std::endl;

    auto it = std::find_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; });
    std::cout << "first even: " << *it << std::endl;

    std::vector<int> squares(v.size());
    std::transform(v.begin(), v.end(), squares.begin(), [](int x) { return x * x; });
    std::cout << "sum of squares: " << std::accumulate(squares.begin(), squares.end(), 0) << std::endl;

    std::vector<Person> people{{"Carol", 27}, {"Alice", 30}, {"Bob", 25}};
    std::sort(people.begin(), people.end(),
              [](const Person &a, const Person &b) { return a.age < b.age; });
    for (const auto &p : people) std::cout << p.name << " ";
    std::cout << std::endl;
}
```

```bash
g++ -std=c++17 -Wall -Wextra algorithms.cpp -o algorithms && ./algorithms
```

These are the four algorithms of the previous exercises, now with the callback where it is used. Compare with `by_age` in the predicates exercise: what do you gain by not having to leave the function, and what do you lose when the lambda gets longer than a few lines? Sort the people by age descending and then by name, in one lambda.

### Task 3: Capture by value and by reference

```c++
// file: capture.cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v{3, 14, 15, 9, 26, 5, 35};
    int limit = 10;

    // [limit]: a copy of limit is stored inside the lambda object
    auto n = std::count_if(v.begin(), v.end(), [limit](int x) { return x > limit; });
    std::cout << "greater than " << limit << ": " << n << std::endl;

    // [&]: the lambda works on the original variable
    int evens = 0;
    std::for_each(v.begin(), v.end(), [&evens](int x) { if (x % 2 == 0) ++evens; });
    std::cout << "evens: " << evens << std::endl;

    // by value: the copy is taken when the lambda is created
    int base = 100;
    auto by_value = [base]() { return base; };
    auto by_ref   = [&base]() { return base; };
    base = 200;
    std::cout << "by value: " << by_value() << ", by reference: " << by_ref() << std::endl;

    // does not compile: a by-value capture is const
    // auto broken = [base]() { base += 1; };

    // sizeof shows the captures
    auto none  = []() {};
    auto one   = [base]() { return base; };
    auto three = [base, limit, &evens]() { return base + limit + evens; };
    std::cout << sizeof(none) << " " << sizeof(one) << " " << sizeof(three) << std::endl;
}
```

```bash
g++ -std=c++17 -Wall -Wextra capture.cpp -o capture && ./capture
```

`[limit]` stores a copy, and this is the answer to the problem that started in the callback exercise: the threshold travels with the callback. `[&evens]` lets the lambda change a variable of `main`. A copy is made when the lambda is **created**, which is why `by_value()` still returns 100 after `base = 200`. The three `sizeof` values show that the captures are members: the lambda with three captures is 16 bytes. Uncomment the line with `broken`, read the error, and explain it.

### Task 4: `mutable` and the state of a lambda

```c++
// file: mutable.cpp
#include <iostream>

int main() {
    int x = 5;

    auto counter = [x]() mutable {       // mutable: the stored copy may change
        x += 10;
        return x;
    };

    std::cout << counter() << " " << counter() << " " << counter() << std::endl;
    std::cout << "outside: " << x << std::endl;

    auto copy = counter;                 // copies the lambda object WITH its state
    std::cout << "original: " << counter() << ", copy: " << copy() << std::endl;
}
```

```bash
g++ -std=c++17 -Wall -Wextra mutable.cpp -o mutable && ./mutable
```

By default the `operator()` of a lambda is `const`, so it may not change its captured copies. `mutable` removes the `const`. The change stays inside the lambda: `x` outside is still 5, while the lambda counts on from call to call. Copying the lambda copies the state, which is why `counter` and `copy` continue from the same value independently. Compare this with the functors `Sum` and `CountingLess` from the previous exercise.

### Task 5: A reference that outlives its variable

```c++
// file: dangling.cpp
#include <functional>
#include <iostream>

std::function<int()> make_safe() {
    int local = 42;
    return [local]() { return local; };        // copy: lives inside the lambda
}

std::function<int()> make_broken() {
    int local = 42;
    return [&local]() { return local; };       // reference to a variable that dies at the closing brace
}

int main() {
    auto safe = make_safe();
    std::cout << "safe:   " << safe() << std::endl;

    auto broken = make_broken();
    std::cout << "broken: " << broken() << "   <- undefined behaviour" << std::endl;
}
```

```bash
g++ -std=c++17 -Wall -Wextra dangling.cpp -o dangling && ./dangling
```

`make_broken` returns a lambda that holds a reference to `local`, a variable that no longer exists once the function returns. Calling it is undefined behaviour: the output above is whatever happened to be on the stack, and your value will differ. Capture by reference only if the lambda cannot outlive the variables: passing it to an algorithm that runs right now is safe, returning it or storing it is not. Explain, for each of the three lambdas in `capture.cpp`, whether it could be returned from a function.

### Task 6: Generic lambdas and init captures

```c++
// file: generic_init.cpp
#include <algorithm>
#include <iostream>
#include <memory>
#include <string>
#include <vector>

int main() {
    // generic lambda: auto parameters make a call operator template
    auto bigger = [](const auto &a, const auto &b) { return a > b; };
    std::cout << bigger(3, 2) << " " << bigger(2.5, 7.5) << " " << bigger(std::string("b"), std::string("a")) << std::endl;

    std::vector<std::string> words{"pear", "fig", "banana", "kiwi"};
    std::sort(words.begin(), words.end(), [](const auto &a, const auto &b) { return a.size() < b.size(); });
    for (const auto &w : words) std::cout << w << " ";
    std::cout << std::endl;

    // init capture (C++14): create a new member in the capture list
    int calls = 0;
    auto next_id = [id = 100, &calls]() mutable { ++calls; return id++; };
    std::cout << next_id() << " " << next_id() << " " << next_id() << " (calls: " << calls << ")" << std::endl;

    // init capture also moves things in
    auto owned = std::make_unique<int>(7);
    auto use = [p = std::move(owned)]() { return *p * 6; };
    std::cout << use() << " " << (owned == nullptr) << std::endl;
}
```

```bash
g++ -std=c++17 -Wall -Wextra generic_init.cpp -o generic_init && ./generic_init
```

With `auto` parameters (C++14) the lambda's `operator()` becomes a template, and one `bigger` works for `int`, `double` and `std::string`. An **init capture** (`[id = 100]`) creates a new member with its own initial value; it is also the way to *move* an object into a lambda, because `[p = std::move(owned)]` captures the `unique_ptr` by move. Why can `std::sort` with the generic lambda `a.size() < b.size()` be used for `std::string` but not for `int`?

## Advice

Write lambdas short, and give them a name with `auto` when you use them twice or when the name explains the intent. Capture explicitly (`[limit, &counter]`) and not with `[=]` or `[&]`, so that a reader sees what the lambda depends on. If a lambda grows beyond a handful of lines, make it a named function or a functor. And whenever a lambda leaves the function in which it was created, check its captures twice.
